## New rules

| ID | Rule | Sources | Status |
|---|---|---|---|
| AP-21 | **Single agent first.** If an agent is needed, start with one agent and tools. Split into several agents only for: prompt logic that branches too much to template, tools that overlap even after their descriptions are fixed, distinct security boundaries, or real parallel specialization | S13, S14, S15 | Firm (three vendors agree) |
| AP-22 | **Deterministic dispatch when the route is known.** If the destination can be decided from the input, use a code router, not an LLM handoff | S14 | Firm |
| AP-23 | **Every loop needs an exit.** Loops, refinement, maker-checker, group chat, swarms and handoff chains need a max iteration count or time limit, explicit acceptance criteria, and a fallback (escalate to a human, or return the best result with a warning) | S14, S15 (extends AP-06) | Firm |
| AP-24 | **No shared mutable state between concurrent agents.** Fan-out needs an explicit merge or conflict-resolution strategy | S14 | Firm |
| AP-25 | **Group chats stay small:** three agents or fewer | S14 | Firm (single T1) |
| AP-26 | **Budget the pattern.** Multi-call patterns (critique, coordinator, hierarchical, swarm) must be justified against latency and cost requirements | S15, S14 | Firm |
| SG-21 | **Risk-rate every tool** low, medium or high, by read vs write, reversibility, permissions and financial impact. High-risk tools pause for checks or a human | S13 | Firm |
| SG-22 | **Layered guardrails** at user input, tool calls, tool responses and final output. No single guardrail is enough | S13, S14 | Firm |
| SG-23 | **Escalate on repeated failure.** After a retry or attempt cap, hand off to a human instead of looping | S13 | Firm |
| SG-24 | **Red-team indirect injection** (instructions planted in documents, email or web content), with multiple attempts per case, since one-shot tests overstate safety | S17 (reporting NIST/UK AISI work) | *Provisional* (T2, check NIST primary sources) |
| SG-25 | **No shared service accounts, and no full user-permission inheritance.** Bind each agent session to the delegating user's scope (for example OAuth scopes bound to a task and time window) | S17 (reporting NCCoE draft) + S4, S5 | Firm (backs up SG-07 and SG-08 with a T1 source) |
| SG-26 | **Evals first, then downsize.** Get a baseline with the most capable model, then swap in smaller models per task only where evals show it holds | S13 | Firm |

## Changed rules

- **AP-13** (tool count). Old: "boundaries blur at roughly 20–50 tools." New: "*Overlap* matters more than count. Some systems manage 15+ distinct tools, while others struggle with fewer than 10 overlapping ones. Fix names and descriptions before splitting." Why: S13 shows count thresholds are anecdotal, and S7 was a single company's report.
- **BB-01** (ladder). New note: "When an agent is warranted, a single agent with tools is the default rung (AP-21)." Why: Microsoft and Google both make that their default.
- **Pattern table.** Added other vendors' names so the reviewer recognizes them: handoff/triage (S13, S14), magentic/task-ledger (S14), group chat/maker-checker (S14), hierarchical decomposition, swarm, ReAct, human-in-the-loop (S15). Also noted that *open-ended doesn't automatically mean a full multi-agent design*. Microsoft says magentic is costly and unsuited to time-sensitive work.
